1基础认知：什么是 B/S？Python 在哪？

B/S = Browser / Server（浏览器 / 服务器架构）

用户不用安装任何软件，用浏览器访问网址即可使用系统；所有业务逻辑和数据处理都放在服务器端。对比 C/S（如微信 PC 版、游戏）需要安装客户端，B/S 维护成本低、跨平台好、改了服务器所有人即时生效。

浏览器(B)
HTML / CSS / JS
决定页面长啥样、按钮怎么点 ⇄ HTTP ⇄ 服务器(S)
Python + MySQL
查库、算账、鉴权、生成合同

Python 在这个 B/S 系统里管的是 S 端

环节Python（Django）在做什么
接收请求接收浏览器 URL 请求，路由到对应函数
业务逻辑判断“用户是不是房东”“押金怎么算”“合同到期没”
操作数据库用 ORM 把房源 / 合同 / 账单存入或查出 MySQL
返回页面把数据填进模板，生成 HTML 发回浏览器
一句话：B/S 说的是系统“长啥样、怎么用”（架构）；Python 说的是服务器那一头“用什么语言写”（实现）。你的题目“基于 Python”＝这个 B/S 系统的服务器端用 Python 实现。就像同一辆汽车，发动机（S 端）你选了 Python 这台。
2系统定位与使用人群
角色职责
租客（普通用户）注册登录、搜索筛选房源、收藏、预约看房、在线签约、交租、申请报修、退租申请

3核心业务流程
选择城市→ 租客注册登录→ 搜索 / 筛选房源（列表 + 地图）→ 收藏 & 预约看房→ 房东确认→ 签订电子合同→ 按月生成账单→ 在线交租→ 报修服务→ 退租 & 押金结算→ 房源重新上架

10部署方案：花生壳内网穿透 + 一键部署

为什么用「花生壳 + 一键脚本」而不是买云服务器

对毕设来说，“演示时系统必须稳稳跑起来” 比 “外网随时能访问” 更重要。花生壳（已验证可用）把本地 Django 端口映射成公网地址，电脑开机即可访问，零成本达成“随时可访问”。答辩当天保持电脑不休眠、提前一天测好域名即可。

花生壳两个坑：① 演示电脑别休眠（电源设“从不睡眠”）；② 免费版域名需提前测试，别现场才连。

一键部署脚本（毕设命门）

把启动流程收敛成一个动作，避免“在我电脑上好好的，现场跑不起来”：

双击 start.bat 自动完成说明
创建虚拟环境检查 / 创建 Python venv，隔离依赖
安装依赖pip install -r requirements.txt（已装则跳过）
数据库迁移python manage.py migrate
灌入演示数据自动生成几个房源、测试账号，无需手动造数据
启动服务runserver 0.0.0.0:8000，浏览器自动打开首页

花生壳映射到 8000 端口，效果即：换一台电脑 → 双击一个文件 → 系统 + 演示数据全部就绪。该脚本在论文里可写成“一键部署脚本设计”章节素材。

名词补充：Nginx + uWSGI（论文可用，本方案不采用）

这是 Python 网站正式上线的经典组合，因为 Django 自带的 runserver 只能用于开发（单线程、不安全、性能差）。生产环境请求链路：

浏览器→ Nginx
门卫：吐静态文件、HTTPS、转发→ uWSGI
管理多个 Django 进程扛并发→ Django 应用→ MySQL

分工逻辑：Nginx 擅长“接待分发”，uWSGI 擅长“跑 Python”（也可用 Gunicorn 替代 uWSGI）。本毕设访问量极小（演示性质），runserver 直接扛得住，无需 Nginx + uWSGI；但它值得写进论文“系统部署”章节，作为对标准上线方案的了解。

前后端分离部署说明（已定方案）

更工程化可用 Docker Compose 一键部署（docker compose up 一条命令拉起 Django + MySQL），显得更专业；但对当前阶段，bat 一键脚本 + 花生壳是最务实组合。注：若仅本地开发，数据库建议用 SQLite（零配置、免装库配库），论文中注明即可；如需 MySQL 再另行安装。
